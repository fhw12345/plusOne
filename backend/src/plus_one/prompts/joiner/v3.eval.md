# Joiner v3 — eval delta (batch-2p + batch-2q)

**Prior version:** `v2.md` (per-language classification only).
**This version:** `v3.md` adds two output channels:
- **batch-2p:** per-item `match_scores: {<person_id>: float in [0, 1]}`.
- **batch-2q:** report-level `tl_dr: string` (single 2–4 sentence paragraph,
  scrapbook voice).

The two surface in the same prompt revision per batch-2q PRD §4.4 ("Do NOT
create `joiner/v4.md` for the second batch — that would mean two prompt
versions in two consecutive batches, doubling the prompt-regression
surface area for no benefit").

## 1. Required deltas to re-baseline before merge

Run the standard joiner eval suite against v3, compare to the last v2
baseline. Report the following in the PR description.

### 1.1 Non-regression on existing classification metrics

| Metric                                     | v2 baseline | v3 measured | Tolerance               |
|--------------------------------------------|-------------|-------------|-------------------------|
| Fused classification F1 (60-place GT)      | record      | record      | ≥ baseline − 2 abs F1   |
| `classification_en` F1 (reddit-only subset)| record      | record      | ≥ baseline − 2 abs F1   |
| `classification_zh` F1 (xhs-only subset)   | record      | record      | ≥ baseline − 2 abs F1   |
| Citation faithfulness (URLs that exist in fetched payload) | record | record | ≥ 99% (no regression) |

The scoring + TL;DR additions add output load; the prompt explicitly
walls them off ("Scoring must use only the loves/hates given. Do NOT use
the evidence list for scoring beyond confirming the candidate matches
its name and style"), but a small F1 drift is the expected risk.

### 1.2 New sanity test — per-person match score range

Hand-labelled fixture set of "obvious" candidate × party combinations.
Each row asserts a one-sided range; the eval passes when ≥ 80% of rows
satisfy their bound.

| Person `hates`        | Candidate style        | Asserted score bound          |
|-----------------------|------------------------|-------------------------------|
| `["seafood"]`         | `"sushi counter"`      | `match_scores[person] ≤ 0.3`  |
| `["crowds"]`          | `"shibuya scramble"`   | `match_scores[person] ≤ 0.3`  |
| `["long queues"]`     | `"ramen with 90m wait"`| `match_scores[person] ≤ 0.4`  |

| Person `loves`        | Candidate style        | Asserted score bound          |
|-----------------------|------------------------|-------------------------------|
| `["ramen"]`           | `"tonkotsu ramen"`     | `match_scores[person] ≥ 0.7`  |
| `["matcha"]`          | `"kissaten matcha"`    | `match_scores[person] ≥ 0.7`  |

Empty loves AND empty hates → expect `0.5` (neutral default — the prompt
nails this exact value).

### 1.3 New sanity test — TL;DR length + voice

Run the eval on N=20 destination queries. For each emitted `tl_dr`:

- **Length:** between 2 and 4 sentences (inclusive). Eval allows 1
  sentence if and only if the destination is single-purpose (e.g.
  "haneda airport").
- **Voice:** all-lowercase first character of each sentence; no `!`;
  no all-caps tokens of length > 1 (proper nouns like "kyoto" are
  expected to be lowercase per the scrapbook voice rule).
- **No card-name leaks:** assert `tl_dr` does NOT verbatim contain any
  `items[i].candidate.name` value — the rule "Do NOT enumerate specific
  candidate names" prevents the TL;DR from rehearsing the cards.

Pass threshold: ≥ 90% of the 20 outputs satisfy all three checks.

### 1.4 Token cost budget

- Per-report **input** tokens: ≤ v2 baseline + 10% (the only added input
  is the `{person_roster}` block — small).
- Per-report **output** tokens: ≤ v2 baseline + 15% (per-item
  `match_scores` map + one `tl_dr` paragraph).
- If either budget regresses by more than the bound, file a tightening
  follow-up before next prompt revision.

## 2. Eval execution — not run in this batch

Per the implementation instructions, the eval suite itself is NOT run
inside this code change. The expectation is that the eval owner (or the
ship reviewer) re-runs it against v3 prior to merging the PR and records
the numbers above in the PR description.

`v2.md` remains on disk for a one-line rollback (`load_prompt("joiner",
"v2")`) if the eval delta surfaces a regression that can't be fixed
forward inside this batch's window.

## 3. Backwards compatibility checks (covered by unit tests)

- `match_scores: None` for old reports → frontend leaves `you only` and
  `them only` tabs empty (current behaviour). Asserted in
  `frontend/lib/trips/categorize.test.ts`.
- `tl_dr: undefined` for old reports → frontend omits the TL;DR sticky
  note entirely. Asserted in
  `frontend/components/trips/ReportView.test.tsx`.
- `translations[lang]: JoinedItem[]` (legacy bare-array shape) →
  frontend zod transform normalises to `{items: [...]}`. Asserted in
  `frontend/lib/schemas/trips.test.ts`.
