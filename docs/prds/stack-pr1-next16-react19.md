# PRD — Stack Migration PR1: Next 14 → 16 + React 18 → 19

**Branch:** `feat/stack-pr1-next16-react19`
**Scope:** Frontend (`frontend/`) framework + React major bump only.
**Author:** PRD Agent (stack-migration team)
**Date:** 2026-05-18

---

## 1. Background

The Plus One frontend currently runs on:

| Package | Installed | Target |
|---|---|---|
| `next` | 14.2.18 | **16.2.x** (latest 16 minor) |
| `react` | 18.3.1 | **19.2.x** |
| `react-dom` | 18.3.1 | **19.2.x** |
| `eslint-config-next` | 14.2.18 | **16.2.x** (match `next`) |
| `@types/react` | 18.3.12 | **19.x** (latest matching React 19.2) |
| `@types/react-dom` | 18.3.1 | **19.x** |
| `typescript` | 5.6.3 | bump to **5.7.x** only if Next 16 / React 19 types require it (Next 16 supports TS 5.1+, so likely no change needed) |

**Why upgrade now?**

- Design system rewrite (Batch 2f, direction D in `docs/design/scrapbook/`) and remaining feature batches will all sit on top of the new framework — better to land the stack bumps first while the UI surface is intentionally minimal (single `app/page.tsx` + `app/layout.tsx`).
- React 19 stable unlocks the new `use()` hook, Actions, `useActionState`, ref-as-prop (no more `forwardRef` boilerplate), and the React Compiler opt-in — all of which PR2 / PR3 will lean on.
- Next 16 stabilises Turbopack for `next build`, ships PPR (Partial Prerendering) graduated, removes legacy options, and aligns the App Router with React 19's async data model.
- Tooling we depend on later (Tailwind 4, TanStack Query v5, `@serwist/next` v9) all target React 19 / Next 15+.

This PR is the **floor** for PRs 2–4; nothing else changes here.

## 2. Goals

1. Bump exactly these dependencies in `frontend/package.json`:
   - `next` → `^16.2.0` (or latest 16.2 patch at time of install)
   - `react` → `^19.2.0`
   - `react-dom` → `^19.2.0`
   - `eslint-config-next` → `^16.2.0`
   - `@types/react` → `^19.0.0` (latest 19.x)
   - `@types/react-dom` → `^19.0.0` (latest 19.x)
   - `typescript` → bump **only if** `pnpm build` or `pnpm typecheck` complains; otherwise leave at 5.6.3.
2. Regenerate `pnpm-lock.yaml` cleanly via `pnpm install` (no manual edits).
3. Apply the minimum config / code changes required for Next 16 to boot (see §4).
4. **Must-pass gates** (Test Agent will verify):
   - `pnpm install` succeeds (no peer-dep errors that block install).
   - `pnpm typecheck` exits 0.
   - `pnpm lint` exits 0.
   - `pnpm build` exits 0 (Next 16 production build of `app/page.tsx` + `app/layout.tsx`).
   - `pnpm test` exits 0 (no tests exist yet — vitest no-op is acceptable).
   - `pnpm dev` boots and `GET /` returns 200 with the existing landing page markup.

## 3. Non-goals

The following are **explicitly out of scope** for this PR and MUST NOT be touched:

- Tailwind / PostCSS upgrade — Tailwind stays at **3.4.14** (PR2 handles 3→4).
- shadcn-style component additions or restyling — UI components are PR2 / Batch 2f.
- State / form / data libs — `zustand`, `react-hook-form`, `zod`, `@tanstack/react-query` are PR3. Do not add or remove.
- PWA — keep `next-pwa@5.6.0` and the existing `withPWAInit` wrapper. PR4 will replace it with `@serwist/next`. If `next-pwa` emits a deprecation **warning** under Next 16, leave the warning; do not work around it. If it hard-**errors** at build time, see §6 risk mitigation (we may temporarily disable the wrapper in dev only, but document and surface to team-lead before doing so).
- ESLint flat config migration — keep legacy `.eslintrc` style; only bump the package version.
- Any change to backend (`backend/`), CI workflows, scripts under `scripts/`, or `docs/design/scrapbook/` assets.
- Adding new pages, components, fonts, images, or env vars.
- Enabling the React Compiler (`reactCompiler: true`) — leave for a later PR after we have real components.
- Enabling PPR (`experimental.ppr`) — not needed for the single static page we have today.

## 4. Technical approach

### 4.1 Files expected to change

| File | Change |
|---|---|
| `frontend/package.json` | Version bumps per §2. No new deps, no removed deps. |
| `frontend/pnpm-lock.yaml` | Regenerated by `pnpm install`. |
| `frontend/next.config.mjs` | Move `experimental.typedRoutes` → top-level `typedRoutes: true` (graduated to stable in Next 15). Keep `withPWA(...)` wrapper, `reactStrictMode`, and `rewrites()` as-is. |
| `frontend/tsconfig.json` | No change expected. (If Next 16's `next-env.d.ts` reference shifts, leave the file alone — Next regenerates it.) |
| `frontend/next-env.d.ts` | Auto-regenerated by `next build`; commit if it changes. |
| `frontend/app/layout.tsx` | No change expected — already typed `Readonly<{ children: React.ReactNode }>`, uses stable `Metadata` / `Viewport` exports. |
| `frontend/app/page.tsx` | No change — pure synchronous server component, no props. |

### 4.2 Next 14 → 16 breaking changes — applicability check

I grepped the entire `frontend/` tree for every documented Next 15/16 breaking surface. Result:

| Breaking change | Pattern grepped | Hits in `frontend/` | Action |
|---|---|---|---|
| Async `params` / `searchParams` in pages, layouts, route handlers, `generateMetadata` | `params:`, `searchParams:` in `app/**` | 0 | None — no dynamic segments exist. |
| Awaitable `cookies()` / `headers()` / `draftMode()` | `cookies()`, `headers()`, `draftMode()` | 0 | None. |
| `useFormState` → `useActionState` rename | `useFormState` | 0 | None. |
| `next/image` prop changes (e.g. removed `layout`, `objectFit`) | `next/image` | 0 (only `next-env.d.ts` reference) | None. |
| `next/font` API tweaks | `next/font` | 0 | None. |
| `geo` / `ip` removed from `NextRequest` | `\.geo`, `\.ip` in `NextRequest` | 0 | None. |
| `experimental.typedRoutes` → stable `typedRoutes` | `experimental` in config | 1 (`next.config.mjs`) | Move out of `experimental` block. |
| Removed `swcMinify`, `appDir`, `serverActions` boolean flags | `swcMinify`, `appDir`, `serverActions` | 0 | None. |
| React 19 PropTypes / defaultProps on function components removed | `defaultProps`, `propTypes` | 0 | None. |
| `React.FC` implicit children removed (React 18 already did this) | `React.FC` | 0 | None. |
| Refs without `forwardRef` (React 19) | `forwardRef` | 0 | None. |

**Net code change beyond `package.json` + lockfile + one `next.config.mjs` tweak: zero expected.** This is exactly why we sequenced PR1 first — the surface area is essentially empty.

### 4.3 Install order (for Code Agent)

```bash
cd frontend
pnpm add next@^16.2.0 react@^19.2.0 react-dom@^19.2.0
pnpm add -D eslint-config-next@^16.2.0 @types/react@^19 @types/react-dom@^19
pnpm install            # regenerate lockfile cleanly
pnpm typecheck
pnpm lint
pnpm build
pnpm test
```

If `pnpm install` flags peer warnings on `next-pwa` (it peers React 18), record the warning but proceed — `next-pwa` continues to function with React 19 in practice; PR4 retires it.

### 4.4 Config edit

`frontend/next.config.mjs` becomes:

```js
import withPWAInit from "next-pwa";

const withPWA = withPWAInit({
  dest: "public",
  disable: process.env.NODE_ENV === "development",
  register: true,
  skipWaiting: true,
});

/** @type {import('next').NextConfig} */
const nextConfig = {
  reactStrictMode: true,
  typedRoutes: true,
  async rewrites() {
    return [
      {
        source: "/api/backend/:path*",
        destination: `${process.env.NEXT_PUBLIC_API_URL || "http://localhost:8000"}/api/:path*`,
      },
    ];
  },
};

export default withPWA(nextConfig);
```

(Only the `experimental: { typedRoutes: true }` block was replaced.)

## 6. Risk + rollback

### Risks

| # | Risk | Likelihood | Mitigation |
|---|---|---|---|
| R1 | `next-pwa@5.6.0` is unmaintained and may hard-fail to load under Next 16 (its `withPWAInit` reaches into internals). | Medium | If `pnpm build` errors trace to `next-pwa`, temporarily set `disable: true` for **all** envs in `next.config.mjs` (the prod PWA was already disabled in dev, and we have no users yet). Document the toggle in the PR description. PR4 retires `next-pwa` entirely. Surface to team-lead before flipping the toggle. |
| R2 | React 19 strict-mode double-invocation surfacing a latent bug in `app/page.tsx`. | Very low | Page is purely static JSX. If anything pops, fix locally; otherwise no action. |
| R3 | `eslint-config-next@16` requires ESLint 9 (flat config). | Medium | If install errors, pin `eslint-config-next` to the latest 16.x patch that still supports ESLint 8; or bump `eslint` to `^9.x` as part of this PR (small, isolated change). Decision deferred to Code Agent at install time — flag to team-lead before broadening scope. |
| R4 | `@types/react@19` types tighten `children` / ref typings and break `app/layout.tsx`. | Low | `RootLayout` already uses `Readonly<{ children: React.ReactNode }>`, which is React-19-correct. If TS complains, narrow on demand. |
| R5 | Turbopack default for `next build` in Next 16 produces output the existing setup doesn't expect. | Low | We don't ship a custom server or rely on webpack-only features. If build fails, fall back to `next build --webpack` and record the issue. |
| R6 | `pnpm-lock.yaml` churn (transitive shifts) makes diff huge. | Certain | Acceptable — lockfile churn is expected for major bumps. Reviewer will skim `package.json` + `next.config.mjs` only. |

### Rollback

Single-PR revert: `git revert <merge-sha>` on `main`. The PR touches only:

- `frontend/package.json`
- `frontend/pnpm-lock.yaml`
- `frontend/next.config.mjs`
- (possibly) `frontend/next-env.d.ts` regenerated

No DB, no API contract, no env var, no infra change. Revert is safe and self-contained.
